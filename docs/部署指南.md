# FrameWeave 部署与使用指南

> 本文档面向**部署本系统的技术人员**。按顺序读完并执行，即可从零把系统跑起来。
> 预计首次部署耗时 1～2 小时（不含域名备案与对象存储开通）。

---

## 一、这是什么

一套**多租户的 AI 创作协作平台**，核心是一块无限画布：用户在画布上放置节点，
每个节点可以生成图片、生成视频、生成语音，节点之间用连线表达「谁是谁的参考素材」。

主要能力：

| 模块 | 说明 |
|---|---|
| 无限画布 | 节点拖拽 / 编组 / 连线 / 一键排序 / 撤销重做 / 分享链接；管理员可在后台恢复画布历史快照 |
| AI 生成 | 文生图、图生图、语音合成；视频六种模式（文生视频 / 图生视频 / 首尾帧 / 参考生视频 / 视频编辑 / 视频延长，见第四章「视频生成模式」） |
| 素材管理 | 个人素材库、团队共享素材库、按项目筛选 |
| 提示词 | 提示词模板、收藏、按分类检索 |
| 多租户 | 用户 / 分组（团队）/ 项目三级隔离，点数配额与计费 |
| 管理后台 | 用户、分组、项目、用量、反馈、内容、系统七大模块 |

技术栈：**Go 1.25（后端）+ Next.js（前端）+ PostgreSQL 18（数据库）+ 对象存储**，
通过 Docker Compose 部署，前后端分离为两个容器。

---

## 二、环境要求

| 项目 | 要求 | 说明 |
|---|---|---|
| 操作系统 | Linux x86_64 | 已在 CentOS / Alibaba Cloud Linux 上验证 |
| Docker | **23.0+** | 需带 `docker compose` v2 插件。构建用到 BuildKit 的 cache mount，23.0 起默认开启；更早版本请先 `export DOCKER_BUILDKIT=1` |
| PostgreSQL | 16+（推荐 18） | **外部提供**，本系统不自带数据库容器 |
| 对象存储 | S3 协议兼容 | 用于存放生成的图片/视频；也可先用本地磁盘 |
| 内存 | ≥ 4 GB | 构建前端时峰值较高，建议 8 GB |
| 磁盘 | ≥ 50 GB | 媒体文件走对象存储时占用很小 |

> **关于 AI 模型**：本系统**不自带任何模型和密钥**，它是一个「壳」——
> 你需要自行准备模型服务商的账号和 API Key，在管理后台配置后才能生成内容。
> 当前版本支持 **OpenAI 兼容协议**（含火山方舟等以 OpenAI 协议提供服务的厂商）。

## 三、首次部署

### 第 1 步：准备数据库

在你的 PostgreSQL 上建一个空库和一个账号：

```sql
CREATE DATABASE frameweave;
CREATE USER frameweave WITH PASSWORD '你自己的强口令';
GRANT ALL PRIVILEGES ON DATABASE frameweave TO frameweave;

-- ⚠️ PostgreSQL 15 及以上必须补这一句，否则建表会失败。
-- PG15 起 public schema 不再默认对所有人开放建表权限，而库的所有者是执行上面
-- CREATE DATABASE 的那个超管、不是 frameweave。漏了这句的表现是【后端根本起不来】：
-- 首次启动自动建表时报 permission denied for schema public，后端进程随即退出，
-- 容器被反复重启；前端要等后端健康检查通过才启动，所以页面也打不开。
-- 确认办法：bash deploy/deploy.sh logs --env prod backend
ALTER DATABASE frameweave OWNER TO frameweave;
```

> 表结构由程序在首次启动时自动创建（AutoMigrate），**不需要手工导入 SQL**。

### 第 2 步：获取源码并生成配置

```bash
git clone <仓库地址> frameweave
cd frameweave
bash deploy/deploy.sh init --env prod
```

这会从 `deploy/env/prod.*.example` 模板生成两个配置文件（并自动填好随机 `JWT_SECRET`）：

- `deploy/compose/prod.env` —— 容器与端口参数
- `deploy/runtime/prod.env` —— 程序运行参数（数据库、密钥等）

### 第 3 步：填写配置

编辑 `deploy/runtime/prod.env`：

```bash
# ── 必填 ──────────────────────────────────────────
DATABASE_DSN=postgres://frameweave:你的口令@数据库地址:5432/frameweave?sslmode=disable

# ⚠️ 这两项不填，系统不会创建管理员账号，你将无法登录后台
ADMIN_USERNAME=admin
ADMIN_PASSWORD=换成你自己的强口令

# JWT_SECRET 已由上一步的 init 自动生成随机值，无需修改。
#（如需自行轮换：openssl rand -hex 32）

# 对外访问地址。它的用途不是"让链接好看"：没配对象存储、或对象存储写入失败时，
# 用户上传的参考图/参考视频会落在本机磁盘上，系统要拼一个【公网可达】的地址
#（形如 https://你的域名/api/media/references/xxx）交给模型服务商自己来抓取。
# 填错、填成内网地址、或域名没解析到这台机器 → 上游抓不到素材，
# 一切依赖参考素材的生成都会失败（图生图垫图、图生视频、肖像授权）。
# 完全不填且又没配对象存储时，上传参考素材会被直接拒绝。
PUBLIC_BASE_URL=https://你的域名

# ⚠️ 建议显式写明。留空时默认信任「回环 + 私有网段」，标准的「Nginx 置前 + 前后端分容器」
#    部署开箱即用；但显式写出来更稳，也便于你在收紧时一眼找到它。
# 后端拿不到浏览器的真实 IP：所有 /api/* 都由前端容器转发过来，后端看到的连接来源
# 恒为【前端容器在 Docker 网络里的 IP】。只有把这个 IP 列进 TRUSTED_PROXIES，
# 后端才会采信 Nginx 传进来的 X-Real-IP；否则全站所有人的 IP 塌缩成同一个值。
# 塌缩的后果很具体：登录失败锁定是按「用户名 + IP」计数的（连续 5 次错误锁 15 分钟）。
# IP 对所有人相同之后，任何人只要知道别人的用户名，连输 5 次错密码就能把那个账号
# 锁死 15 分钟，而且可以一直续下去——包括你的管理员账号。
# 短信验证码的「单 IP 每日上限」（默认 100 条）也会从"每人 100 条"变成"全平台共 100 条"。
# 取值：支持精确 IP，也支持 CIDR 网段（逗号分隔，两种可混用）。
# 【推荐写网段】：前端容器的 IP 由 Docker 动态分配，容器重建后可能变化；
# 只写死单个 IP 的话，重建之后这份名单会【静默失效】、IP 再次塌缩，而且没有任何报错。
#   TRUSTED_PROXIES=172.16.0.0/12,127.0.0.1,::1
# 想查当前实际 IP 的话：
#   docker inspect -f '{{range .NetworkSettings.Networks}}{{.IPAddress}}{{end}}' frameweave-prod-frontend-1
#
# 另外：这一项【留空时】默认信任「回环 + 私有网段」，对标准的
# 「Nginx 置前 + 前后端分容器」部署来说开箱即用。之所以安全，是因为 compose 里
# 后端只 expose 不 publish、公网打不到它。⚠️ 如果你把后端端口直接发布到公网
# （不建议），务必在这里显式收紧。
TRUSTED_PROXIES=172.16.0.0/12,127.0.0.1,::1

# ── 对象存储（推荐配置；不配则媒体文件落本地磁盘）──
# ⚠️ 注意：STORAGE_DRIVER 是【数据库驱动】，不是对象存储开关，保持 postgres 不要动。
#    对象存储只需填下面这几项 TOS_*。
# TOS_BUCKET=
# TOS_REGION=cn-beijing
# TOS_ENDPOINT=tos-s3-cn-beijing.volces.com
# TOS_ACCESS_KEY=
# TOS_SECRET_KEY=
# TOS_PUBLIC_BASE=https://你的桶的公网域名
```

再编辑 `deploy/compose/prod.env`：

```bash
APP_DATA_DIR=/data/frameweave/prod/app-data   # 宿主机上的应用数据目录（默认模板即此值）
FRONTEND_PORT=127.0.0.1:3000              # 只监听本机，前面用 Nginx 反代
```

> **`APP_DATA_DIR` 是什么**：它会被挂载成后端容器里的 `/app/data`。用户上传与生成的媒体
> （`sync-files/`）、交给模型服务商拉取的参考素材（`reference-media/`）、提示词封面
> （`prompt-covers/`）、后端日志（`logs/`）全都落在这里。**它必须和数据库一起备份**，
> 详见第六章「备份」。换目录前先把原目录整份搬过去。

> **安全提示**：`FRONTEND_PORT` 保持 `127.0.0.1:` 前缀。写成裸 `3000` 会绑定到
> `0.0.0.0`，等于把服务直接暴露在公网上，绕过你的 Nginx 与 HTTPS。

### 第 3.5 步：改成你自己的品牌名（可选）

默认品牌名是「FrameWeave」，它出现在浏览器标签页标题、首页大标题、顶栏、后台侧栏、
画布水印、新建画布的默认名、导出文件名，以及 AI 排版助手的自我介绍里。

改名只需要编辑一个文件：

```bash
echo "你的品牌名" > web/APP_NAME
```

> ⚠️ **这是构建期配置，不是运行时配置**。改完必须重新构建前端镜像才会生效：
> ```bash
> bash deploy/deploy.sh build --env prod frontend
> bash deploy/deploy.sh up --env prod all
> ```
> 只改文件、只重启容器是不会变的。

换 logo：替换 `web/public/logo-mark.svg`（方形图标，用在登录页和顶栏），
以及 `web/src/app/icon.svg`、`web/src/app/favicon.ico`（浏览器标签页图标），同样需要重新构建前端。

### 第 4 步：构建并启动

```bash
# 基础镜像（装依赖，只需做一次；依赖变更时才需重做）
bash deploy/deploy.sh build-base all

# 应用镜像
bash deploy/deploy.sh build --env prod all

# ⚠️ 启动前务必核对 compose 实际引用的镜像标签
bash deploy/deploy.sh config --env prod | grep image:

# 启动
bash deploy/deploy.sh up --env prod all
```

> **为什么要核对镜像标签**：`build` 只是产出镜像，`up` 用的是配置文件里记录的标签。
> 两者不一致时会出现「构建成功了但跑起来还是旧代码」，且没有任何报错。
> 养成 build → config 核对 → up 的习惯。

> ⚠️ **`build-base` 不能跳过，即使机器上已经有同名的基础镜像。**
> 基础镜像固定用 `:current` 标签、不区分环境，所以同一台机器上如果还跑着**另一套**部署，
> 那个 `:current` 是**别人的**——里面烘的是别人那套的 Go 模块信息。
> 直接跳到 `build` 的表现很具体：后端编译当场失败，报
> `package xxx/config is not in std (/usr/local/go/src/xxx/config)` 一连串。
> 反过来，在这台机器上执行 `build-base` 会**覆盖**那个共用标签，导致另一套下次构建时同样出错。
> 所以：**一机一套时直接跑；一机多套时，跑之前先备份、用完还原**：
> ```bash
> docker tag frameweave-backend-base:current  frameweave-backend-base:bak
> docker tag frameweave-frontend-base:current frameweave-frontend-base:bak
> # …build-base / build / up…
> docker tag frameweave-backend-base:bak  frameweave-backend-base:current
> docker tag frameweave-frontend-base:bak frameweave-frontend-base:current
> ```

### 第 5 步：验证

```bash
bash deploy/deploy.sh ps --env prod                    # 两个容器都应是 healthy
curl -s http://127.0.0.1:3000/api/version              # 返回 buildId
bash deploy/deploy.sh logs --env prod backend          # 看启动日志（打完就退出）
```

### 第 6 步：配置 Nginx 反向代理（示例）

```nginx
server {
    listen 443 ssl http2;
    server_name 你的域名;

    ssl_certificate     /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    client_max_body_size 600M;   # 画布同步与大文件上传需要；单文件真实上限见下方说明

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_read_timeout 600s;   # 视频生成是长连接，不能用默认 60s
    }
}
```

> **关于上传体积上限**：单个文件的真实上限是 **300MB**，由三道闸共同决定：
>
> 1. Nginx 的 `client_max_body_size`（建议 600M，给 multipart 封装和画布整包同步留余量）；
> 2. `deploy/runtime/prod.env` 里的 `PROXY_MAX_UPLOAD_MB`（默认 300，前端代理层的闸门）；
> 3. 写死在代码里的 300MB 硬上限（后端接收端与画布客户端各一道，改配置无法绕过）。
>
> 所以**把 `PROXY_MAX_UPLOAD_MB` 往上调是无效的**——文件还是会被第 3 道拦下；
> 只把 Nginx 调大同样无效。超过 300MB 时用户看到的提示是
> 「上传内容过大（上限 300MB），请压缩后重试」。
> 反过来，如果想收得更紧，把 `PROXY_MAX_UPLOAD_MB` 往下调是有效的。

## 四、启动后必做：配置模型渠道

**系统初次部署后是一个空项目，没有任何模型配置。不配渠道就无法生成任何内容。**

1. 用 `ADMIN_USERNAME` / `ADMIN_PASSWORD` 登录，进入 `/admin`

2. 打开「**分组管理**」，点右上角「**新建分组**」。分组是团队单位，模型渠道配在分组上，
   **未分组的用户无法调用任何 AI 能力**。

3. 在分组列表里点该行的「**编辑**」，在弹窗的「**模型渠道（本组专属）**」一节点
   「**添加渠道**」，填写：

   | 字段 | 填什么 |
   |---|---|
   | 渠道名称 | 自己起，如「主力渠道」 |
   | BaseURL | 服务商给的接口地址，通常填到 `/v1` |
   | 协议 | 「**OpenAI 兼容**」或「**火山音频**」。做图片 / 视频 / 文本选前者；做**音频生成**必须选后者，配法见 §四·二 |
   | API Key | 服务商给的密钥 |
   | 模型列表（逗号或换行分隔） | 该渠道可用的模型名 |

   右下角的开关控制这条渠道「启用 / 停用」，填完点弹窗底部「**保存**」。

   > ⚠️ **同一个视频模型名只挂在一个渠道上。** 视频是异步任务，查询进度时系统按模型名重新挑渠道；
   > 同名模型挂在两个渠道上，查询可能落到另一家，查不到任务就会被判为失败并退点
   > （片子其实可能还在原渠道生成）。图片、文本这类同步请求不受影响。

4. **确认渠道是通的**：填好 BaseURL 和 API Key 后，点「模型列表」右上角的
   「**拉取模型**」。它会用你填的地址和密钥去调上游的 OpenAI `/models` 接口，
   把可用模型拉回来供勾选——**能拉回列表，就说明地址和密钥是通的**。
   上游不提供 `/models` 接口时，在弹窗里手工输入模型名即可。

   > 后台**没有**逐个模型做生成测试的按钮，模型本身是否可用以实际生成为准。
   > 同一个弹窗下方那个「**测试连通**」按钮属于「对象存储桶」一节，测的是桶而不是模型渠道。

5. 打开「**系统 → 分级定价**」配单价（消耗多少点数）：图片模型在
   「**模型点数（按次）**」表里按次配；视频模型在「**视频模型按秒计费**」表里
   按分辨率档配（每档还分「无输入 / 带视频」两个价）；**音频模型见 §四·二 第 5 步**
   （可按次、按字数或按秒，三选一）。

   > ⚠️ **视频模型必须逐个分辨率档位配价。** 请求的分辨率在该模型的价格表里找不到时，
   > 系统不报错，而是静默回退：**先按 720p 档的单价**计费；连 720p 档也没配，
   > 就用该模型价格表里的**第一个档位**。也就是说，放开 1080P / 2160P（4K）却没给这两档
   > 配价，结果是**按 720p 的单价收高清片的钱**，日志里看不出任何异常。
   > 另外，档位在表里但单价填的是 0，就是按 0 收费（等于免费出片）；
   > 该模型在这张表里一个档位都没有时，整体回退成按次计费；**按次价也没配，就是按 0 点收费**，
   > 所有人都能免费用这个模型，而上游照样向你的账号计费。**新加任何模型，先配价再开放给用户。**

6. 打开「**用户管理**」，点「**新增**」创建用户并分配到分组。

7. **给用户加点数是独立的一步**：新建用户的弹窗里没有额度输入框，创建时也填不了。
   要在用户列表里点该行的「**编辑**」（铅笔图标），在弹窗底部的「**点数调整**」一节，
   往「点数」输入框里填**目标余额**（这是绝对值，不是增量），再点旁边的「**调整**」。
   点「保存」只保存用户资料，不会改点数。

## 四·二、配置音频生成（火山「豆包语音」）

> **先看这一段再动手。** 音频用的是火山引擎的**语音技术**产品线，和图片 / 视频用的**方舟（Ark）
> 是两套完全独立的东西**：不同的控制台、不同的密钥、要单独开通、接口地址也不一样。
> 拿方舟的 API Key 来配音频，一定不通。这一节把整条链路从头写清楚。

### 0. 能做什么

配好之后，画布上的**音频节点**支持三种用法：

| 用法 | 怎么用 | 模型 |
|---|---|---|
| **文字 → 语音** | 写台词，选音色 | `doubao-tts`（豆包语音合成） |
| **参考音频 → 同音色语音** | 拖一个音频节点连到目标节点，提示词里写 `@音频1`，模型会用那段声音的音色和语气念新台词 | `seed-audio-1.0`（音频生成） |
| **参考图片 → 音频** | 接一张图片，按图片内容生成音频 | `seed-audio-1.0` |

> ⚠️ 参考图片和参考音频**不能同时用**（上游限制），接了两种时系统只发音频参考并弹窗告知。

### 1. 开通（这一步在火山控制台做，不在本系统里）

1. 登录火山引擎控制台，进入 **语音技术**（不是"方舟"，别走错）
2. 开通 **语音合成**（给 `doubao-tts` 用）
3. **单独开通「音频生成」**（给 `seed-audio-1.0` 用）——这是独立的一项资源，
   开通语音合成**不会**自动带上它
4. 进入 **控制台 → API Key 管理**，创建一个 **X-Api-Key**

> **两个最容易卡住的地方：**
> - 没开通「音频生成」时，调用会报 `403` + `45000030`，提示
>   `[resource_id=volc.service_type.10074] requested resource not granted`。
>   本系统已把它翻成中文「**火山账号尚未开通「音频生成」服务**」。看到这句就是去控制台开通。
> - **刚开通后有几分钟的生效延迟**，期间还会报同样的 403。等几分钟重试，不要以为配错了。
>
> 顺带一提：语音合成和音频生成**共用同一把 X-Api-Key**，不需要申请两个密钥。

### 2. 在本系统里添加渠道

「**分组管理**」→ 编辑分组 → 「模型渠道」→ 「添加渠道」：

| 字段 | 填什么 | 说明 |
|---|---|---|
| 渠道名称 | 自己起，如「火山音频」 | |
| **协议** | **火山音频** | 选错的话请求会被当成 OpenAI 格式发出去，必失败 |
| **BaseURL** | `https://openspeech.bytedance.com` | **可以留空**，留空时系统用这个默认值。注意**不要**填方舟的 `ark.cn-beijing.volces.com` |
| **API Key** | 语音技术控制台的 **X-Api-Key** | **不是**方舟的 API Key，也不是 AK/SK |
| **Resource-Id** | 留空即可 | 只在用 `doubao-tts` 时有意义（默认 `seed-tts-1.0`；用「声音复刻」音色时填 `seed-icl-2.0`）。音频生成不看这个值 |
| **模型列表** | `seed-audio-1.0` 和/或 `doubao-tts` | 逗号或换行分隔 |

> 这个协议下**「拉取模型」按钮不可用**——火山语音技术没有 OpenAI 那种 `/models` 接口。
> 请手工输入模型名。

### 3. 标记模型类型（**漏了这一步模型不会出现在音频下拉里**）

「**系统 → 分级定价**」→ 最上面的「**模型类型与可用档位**」表 →
找到 `seed-audio-1.0`，把「类型」改成「**音频**」。

> 系统对没标类型的新模型有名字启发式兜底（名字里含 `audio` / `tts` / `speech` / `voice`
> 会被猜成音频），所以 `seed-audio-1.0` 通常能自动判对。但**建议手工确认一遍**：
> 判错的话，这个模型会出现在错误的分类下拉里，用户根本选不到它。

### 4. 配置画布上的音频参数

用户在音频节点的设置里可以调：

| 参数 | 取值 | 说明 |
|---|---|---|
| 输出格式 | MP3 / WAV / Opus / PCM | |
| **采样率** | 各格式可选档不同 | WAV/PCM 有 8k~48k 共 7 档；MP3 没有 40k；**Opus 只有 48k**。换格式时系统会自动把采样率落到新格式的合法值 |
| 语速 | 0.5x ~ 2.0x | 对应上游 `speech_rate` [-50, 100] |
| 音量 | -50 ~ 100 | 0 = 不调整 |
| 音调 | -12 ~ 12 | 0 = 不调整 |

> **没有「时长」这个参数。** 上游不提供时长控制，我们实测过：用自然语言在提示词里写
> 「总时长约 N 秒」时灵时不灵（尤其接了参考音频时），所以没有把它做成一个会骗人的开关。
> **出片多长完全由文本长度决定。**

### 5. 配置音频计价（**三选一，优先级：每 100 字 > 每秒 > 按次**）

「**系统 → 分级定价**」→ 「**音频模型按秒计费**」表。每个音频模型有两个输入框：

| 计价方式 | 怎么配 | 适合 |
|---|---|---|
| **按字数**（推荐） | 「每 100 字积分」填 >0，「每秒点数」留 0 | 扣费 = ⌈字数 ÷ 100⌉ × 单价，**不足 100 字按 100 字算**。字数在提交时就知道，一次扣准，没有预扣和退款，用户界面上还能实时看到字数和将扣的积分 |
| **按秒** | 「每 100 字积分」留 0，「每秒点数」填 >0 | 扣费 = 出片秒数 × 单价。因为秒数事前不可知，系统会先按默认 15 秒**预扣**，出片后按真实时长**结算差额**（多退少补），点数日志里会看到一扣一退两条 |
| **按次** | 两个都填 0 | 回退到「模型点数（按次）」表里的一口价，不管出片多长都收一样的钱 |

> **建议用按字数。** 它是三者里唯一"所见即所得"的：用户在输入框下方能实时看到
> `123/2000 字`，心里有数；而且不会出现"预扣一大笔再退回来"让用户困惑的流水。

### 6. 验证

新建画布 → 双击空白处 → 选「音频参考」建一个音频节点 → 模型选 `seed-audio-1.0` →
写一句话 → 点生成。出片后：

- 节点上能播放、能下载
- 「**系统 → 任务日志**」里能看到这次调用（模型、状态、耗时、请求摘要）
- 用户自己在头像菜单「**我的消耗**」里能看到这次的扣费

### 7. 两条硬限制（会直接影响用户体验，建议告知使用者）

1. **文本上限 2000 字**。超了生成按钮会禁用，计数器变红。
2. **出片上限 120 秒**，这是上游的硬限制。
   ⚠️ **注意这两条会打架**：中文正常语速约 3.8 字/秒，**约 450 字就会超过 120 秒**
   （实测 300 字 = 78.6 秒可以过，500 字直接被拒）；英文约 9.5 字符/秒，能到 1100 字符左右。
   也就是说**中文远不到 2000 字就会撞时长墙**。
   系统会在文本接近这条线时把字数计数器标黄提示；真撞上时，上游返回的
   `DurationOutOfRange` 已被翻成中文「文本太长了……请分段生成（中文大约 450 字以内）」。
   **长文本请分段生成。**

### 图片画质档与实际分辨率

画布上的图片节点有 **1K / 2K / 4K** 三档画质和 7 种比例。这里的档位名指的是
**总像素量**，不是边长——所以同一档下换比例，出图的边长会变、像素总量基本不变。

| 比例 | 1K | 2K | 4K |
|---|---|---|---|
| 1:1 | 1440×1440 | 1920×1920 | 2880×2880 |
| 3:2 | 1760×1176 | 2344×1560 | 3520×2344 |
| 2:3 | 1176×1760 | 1560×2344 | 2344×3520 |
| 4:3 | 1656×1240 | 2216×1664 | 3320×2488 |
| 3:4 | 1240×1656 | 1664×2216 | 2488×3320 |
| 16:9 | 1920×1080 | 2560×1440 | 3840×2160 |
| 9:16 | 1080×1920 | 1440×2560 | 2160×3840 |

档位名的由来是 16:9 那一列的标准分辨率：1K=1920×1080、2K=2560×1440、4K=3840×2160。
其余比例按「像素总量相同」换算，再把边长对齐到 8 的倍数。

> **容易误会的一点**：选 2K + 1:1 出来是 **1920×1920** 而不是 2048×2048。
> 这是对的——1920×1920 ≈ 369 万像素，与 2K 标准的 2560×1440 像素量一致。
>
> 之所以按像素量而不是按边长定档，是因为**上游计费和耗时都跟像素数成正比**。
> 如果按边长定，1:1 的 2048×2048（419 万像素）会比 16:9 的 2560×1440（369 万像素）
> 贵 14%，但界面上都显示「2K」、也按同一档收费，账就对不上了。
> 现在同一档下不论选什么比例，像素量浮动不超过 1%（只来自 8 像素取整），成本可控。

几个硬性限制（超出会在生成前直接报错，不会白扣点数）：

- 宽高都必须是 **8 的倍数**
- 最长边 **≤ 3840px**
- 宽高比 **≤ 3:1**
- 总像素在 **655,360 ~ 8,294,400** 之间

上面 21 个组合全部在范围内。另外两类模型有各自的额外约束，系统会自动处理：
Seedream 系要求 ≥ 369 万像素，低于此的档位会被等比放大；gpt-image 系的边长会对齐到它要求的步长。

### 视频生成模式

视频节点（以及「视频生成页」）的「视频设置」里有一组「**模式**」按钮，用来声明
**这一单要让模型做什么**。各模式对参考素材的要求、以及上游给的硬性约束都不一样：

| 模式 | 要接入的参考素材 | 输出比例 | 输出时长 |
|---|---|---|---|
| **文生视频** | 不接任何参考素材 | 自己选 | 自己选 |
| **图生视频** | 图片节点 **1 个**（作首帧）；不能接视频/音频 | **强制自适应**（跟随首帧图） | 自己选 |
| **首尾帧** | 图片节点 **1~2 个**（1 张 = 只定首帧、尾帧由模型续写；2 张 = 首帧 + 尾帧）；不能接视频/音频 | **强制自适应**（跟随首帧图） | 自己选 |
| **参考生视频** | 图片 / 视频 / 音频 **至少 1 个**，当作内容参考（人物、场景、风格） | 自己选 | 自己选 |
| **视频编辑** | 视频节点 **1 个** —— 待编辑的那段，时长必须 **4~30 秒**；不能接图片/音频 | **强制自适应**（跟随源视频） | **由源视频决定**，界面上选的秒数不生效 |
| **视频延长** | 视频节点 **1 个** —— 要续写的那段；不能接图片/音频 | **强制自适应**（跟随源视频） | 自己选（= 成片**总**长度，不是在源片之外再加这么多） |

> **「强制自适应」是上游的规矩，不是系统给用户加的限制**：这几种模式下输出画幅必须跟随首帧图
> 或源视频，上游要求比例参数传「自适应」，传别的值是**当场报错**而不是静默回退。
> 所以系统会在**请求发出去的时候**把比例改成自适应，并在比例选择器旁写明原因。
> 你在界面上选的那一档不会被改写——切回别的模式，原来选的比例还在。
> 分辨率（清晰度档）不受影响，它是计费口径，任何模式下都按你选的那一档发、按那一档收费。

**模式怎么选**：

- 默认是「**文生视频**」。
- **一接入参考素材就自动变成「参考生视频」**——这是最常用、语义最保守的一档。
- 想用「图生视频 / 首尾帧 / 视频编辑 / 视频延长」，**必须自己点**：
  **系统不会按素材数量替你猜**。这是有意的：同样是「接了两张图」，既可能是「首帧 + 尾帧」
  （画面从 A 渐变到 B），也可能是「人物图 + 场景图」（把两张的内容都当参考）。
  两种语义出片完全不同，而猜错了**不会报任何错**——片子是错的、点数照扣，事后也无从查起。
- 素材不满足某个模式时那个按钮是灰的，鼠标悬停会写明差什么
  （例如「首尾帧需要连接图片节点（1~2 个），当前 3 个」）。
- 选了某个模式之后又把素材改到不满足（比如选了「图生视频」再接上第二张图），**点生成会直接报错**，
  不会偷偷换成别的模式发出去——按钮上写着什么，发出去的就是什么。
- 「首尾帧」接 2 张图时，点参考图下方的「**首帧 / 尾帧**」角标可以对调；只接 1 张时角标写着
  「首帧」、不可点。**别靠连线顺序碰运气**：首尾搞反了片子是倒着走的，界面上看不出来。

**哪些模型有哪些模式**：

| 模型 | 可选模式 |
|---|---|
| Seedance **2.5** 系（模型名里带 `seedance-2-5`） | 六种全有 |
| Seedance 2.0 系（含 fast / mini） | 前四种；**没有**「视频编辑」「视频延长」 |
| 其它走 OpenAI 兼容协议的视频模型 | 只有「文生视频」——这类接口没有「模式」这个概念 |

> 「视频编辑」「视频延长」对应的是 Seedance 2.5 才有的任务类型字段，2.0 系的请求体里根本没有它，
> 多发一个不认识的顶层字段可能整单被拒。所以这两个按钮在 2.0 系上**不会出现**——不是藏起来了，
> 是那些模型确实不支持。
>
> 只有「文生视频」那一档的模型**照样可以接参考图**（参考图仍按原样发给上游，用不用由上游决定），
> 只是没有模式可选，界面上那一格始终停在「文生视频」。



**编辑 / 延长对提示词有硬性要求（上游的规矩）**：

上游收到请求时只做一次前置校验，**真正跑任务时模型还会结合提示词再判一次任务类型**，
判出来跟声明的不一致就失败。关键在于这次失败是**异步**的：提交是成功的、点数已经扣了，
几十秒后才失败（失败会走正常的视频退款流程退回）。所以提示词里要写明意图：

| 模式 | 提示词里要出现的意图词 |
|---|---|
| 视频编辑 | 编辑视频、增加 / 加上、删除 / 去掉、修改 / 替换 / 改成 |
| 视频延长 | 向前延长 / 向后延长、延续、续写 |

提示词里没有这类词时，界面会在生成前给一句提醒（**只提醒、不拦截**——关键词表是示例不是白名单，
「把画面里的狗换个颜色」这种明显是编辑、只是没写「替换」二字的写法不该被误伤）。

**计费口径（这两档和别处不一样，务必看清）**：

- **视频编辑按「待编辑视频的真实时长」收费**，不是按界面上那个秒数。上游要求这一档的时长参数
  交给模型自己定，输出时长与源视频完全一致（实测 4.06 秒的源片出 4.06 秒的成片），
  所以服务端会在**扣费与提交之前**读取源视频的真实时长，按它计费（不足 1 秒按 1 秒，向上取整）。
  - **读不到时长就直接拒绝生成、一个点数都不扣**，提示是「无法读取待编辑视频的时长……本次未扣除点数」。
    这是有意的：不知道片子多长就没有任何诚实的收法，宁可拒绝，也不按一个编出来的默认秒数收钱。
  - 源视频不在 **4~30 秒**区间同样是当场拒绝、不扣费，提示里会写出实际读到的秒数。
    上游本来也会拒，但那是一次异步失败（钱先扣、几十秒后才失败再退），不如当场说清楚。
- **视频延长按界面上选的秒数收费**。⚠️ 实测那个秒数是**成片总长度**、不是增量：
  源片 4.06 秒、选 6 秒，出来的是一段 6.00 秒的片子。所以界面上的秒数就是最终成片长度，
  也就是计费长度，与其它模式口径一致。
- 其余四种模式的计费口径一个字没变：按所选秒数 × 所选分辨率档的单价。

**参考视频会被上游做真人 / 隐私检测**：含真人的视频拿去做编辑或延长可能被**直接拒收**，
报错里会写「参考视频疑似包含真人或隐私信息」。**这是模型平台的内容策略，不是系统故障**——
换一段不含真人的素材即可，重试、换分辨率、改提示词都没有用。

另外，参考视频的**单条**时长上限跟着模型走（2.0 系 15 秒、2.5 系 30 秒），
「视频编辑」那一档另有 4~30 秒的专属区间（见上）。

### 节点上的「设置」按钮（合并后的样子）

画布上点开一个图片 / 视频节点，下方操作面板里**只有一个设置按钮**，
折叠时显示这一单的摘要，点开才是完整面板：

| 节点 | 按钮上的摘要长这样 | 点开后能调 |
|---|---|---|
| 视频节点 | `参考生视频 · 16:9 · 720P · 5s · 🔊` | 模式、比例、清晰度、时长、生成声音 / 水印 |
| 图片节点 | `2K · 1:1 · 1 张` | 画质、尺寸、生成张数 |

几点看摘要时要知道的：

- **模式只在不是「文生视频」时才占一段**。按钮宽度有限，天天挂一句「文生视频」
  只会把后面的比例 / 清晰度 / 时长挤没；而一旦落到「参考生视频」或用户显式选了别的模式，
  那就是这一单最要紧的信息，排在最前面。
- 末尾的 🔊 表示**这一单会生成声音**；没有这个图标就是不生成。
- 摘要里的比例是**你选的那一档**。「强制自适应」的几种模式只在请求发出去时改写，
  不动你选的值（原因见上一节），所以摘要与选择器始终一致。

| **开启手机验证码登录注册** | **开启** | 登录页会显示「手机验证码」入口。但没在「私有配置 → 火山引擎短信服务」里启用短信服务时，点了会报「短信服务未启用，请联系管理员开通」。不用就关掉，避免用户撞上死入口：系统 → 系统设置 → 「公开配置」→ 「开启手机验证码登录注册」。 |
| **是否允许用户自定义渠道** | **开启** | 开启后，普通用户可以在「配置与用户偏好」里切到「本地直连」，填自己的 Base URL 和 API Key 直连上游。**走这条路不扣点数、不产生任务日志、也不留审计记录**。除非你确实要给用户这个能力，上线前关掉：系统 → 系统设置 → 「公开配置」→ 「是否允许用户自定义渠道」。 |
| 开启定时同步（提示词） | 关闭 | 会定时拉取第三方 GitHub 提示词仓库并下载封面（首次数百 MB）。需要再开：系统 → 系统设置 → 「私有配置」→ 「提示词定时同步」。 |
| 肖像授权 | 关闭 | 依赖火山方舟的人像资产库。凭证按分组配置：分组管理 → 「编辑」→ 「火山方舟人像资产凭证」；也可在 `deploy/runtime/prod.env` 里用 `VOLC_*` 配一份全局默认。 |

## 五、管理后台功能说明

| 菜单 | 作用 |
|---|---|
| **用户管理** | 增删改用户、分配分组、充值点数、设置角色（超管 / 二级管理员 / 普通用户） |
| **分组管理** | 团队单位。配置该组专属的模型渠道、火山方舟人像资产凭证、对象存储桶 |
| **项目管理** | 项目级的点数池，可让多个用户共用一份配额 |
| **用量分析** | 点数日志、生成统计、任务日志（含每次调用的请求摘要与耗时） |
| **用户反馈** | 用户在前台提交的问题，附带其操作日志与现场快照 |
| **内容管理** | 提示词模板、收藏提示词、素材库、画布历史 |
| **系统** | 系统设置、分级定价、操作审计、短信记录 |

**角色说明**：

- **超管**：七个菜单全部可见，全部权限。
- **二级管理员**：左侧只看得到 **用户管理 / 分组管理 / 项目管理 / 用量分析 / 用户反馈** 五项；
  **内容管理**和**系统**两个菜单是超管专属，不会出现在他的侧栏里（也就是说系统设置、
  分级定价、操作审计、短信记录、素材库与画布历史他都碰不到）。
  可见的那五项里，他只能管理自己创建的用户与分组，只看得到下辖用户的数据。
  另外，超管可以把某条渠道设为「对二级管理员隐藏」，隐藏后该渠道连密钥都不会下发给他。
- **普通用户**：进不了 `/admin`，只能使用前台画布。

## 六、日常运维

### 升级到新版本

```bash
# 1. 先备份：数据库 + 应用数据目录，两样都要（见下面「备份」一节）
#    库名/账号按你自己建库时用的替换；数据目录按你在 deploy/compose/prod.env 里配的 APP_DATA_DIR 替换。
#    ⚠️ 用与数据库同版本的 pg_dump，原因见「备份」一节。
docker run --rm -e PGPASSWORD='你的口令' postgres:18 \
  pg_dump -h <主机> -U frameweave frameweave | gzip > backup-$(date +%Y%m%d).sql.gz
tar czf appdata-$(date +%Y%m%d).tar.gz -C /data/frameweave/prod app-data

# 2. 依赖清单有变化时，必须先重做基础镜像
#    触发条件：go.mod / go.sum / web/package.json / web/bun.lock 任一有改动。
#    看不出有没有改动就直接跑一遍——只是慢一点，没有副作用。
#    基础镜像不存在时，下一步的 build 会直接报「未找到基础镜像 …；先执行 deploy.sh build-base」。
bash deploy/deploy.sh build-base all

# 3. 替换源码后重新构建
bash deploy/deploy.sh build --env prod all
bash deploy/deploy.sh config --env prod | grep image:   # 核对标签
bash deploy/deploy.sh up --env prod all
```

### 回滚

`deploy.sh` 每个应用保留最近两版镜像。回滚前先给当前版本打标签：

```bash
docker tag $(docker inspect frameweave-prod-backend-1 --format '{{.Image}}') frameweave-backend:rollback
docker tag $(docker inspect frameweave-prod-frontend-1 --format '{{.Image}}') frameweave-frontend:rollback
```

回滚时把 `deploy/runtime/releases/prod.env` 里的镜像标签改回上一版，再 `up`。

### 备份

**要备份的是两样东西，少一样恢复时就会丢数据：**

| 备份对象 | 装的是什么 |
|---|---|
| **PostgreSQL** | 用户、分组、项目、点数余额与流水、画布结构与历史快照、全部后台配置（含渠道密钥） |
| **`APP_DATA_DIR`** —— `deploy/compose/prod.env` 里配的那个宿主机目录，挂载为容器内 `/app/data` | 用户上传与生成的媒体文件（`sync-files/`）、交给模型服务商拉取的参考素材（`reference-media/`）、提示词封面（`prompt-covers/`）、后端日志（`logs/`） |

只备份数据库的话，恢复出来的画布**结构还在，但图片和视频全都打不开**——
节点里记着文件地址，文件本身却没了。

配了对象存储之后，新生成的媒体大多直连进桶、由云厂商保证可靠性，但 `APP_DATA_DIR`
**仍然必须备份**：提示词封面始终落在本机，而且对象存储写入失败时系统会回退落盘，
这些文件只存在这个目录里。

```bash
# 数据库（库名/账号按你自己建库时用的替换）
# ⚠️ pg_dump 的版本不能低于数据库服务端。系统自带的 pg_dump 往往是旧版（例如 13），
#    对 18 版的库会直接报 server version mismatch 并中止，所以用同版本的官方镜像来跑最省事。
#    数据库就在这台机器上时，再加一个 --network host。
docker run --rm -e PGPASSWORD='你的口令' postgres:18 \
  pg_dump -h <主机> -U frameweave frameweave | gzip > backup-$(date +%Y%m%d).sql.gz
# 应用数据目录（路径按你在 deploy/compose/prod.env 里配的 APP_DATA_DIR 替换）
tar czf appdata-$(date +%Y%m%d).tar.gz -C /data/frameweave/prod app-data
```

建议每天一次，异地保留 7 天以上。**并且定期做一次恢复演练**——
没演练过的备份等于没有备份。

恢复（先恢复到一个**新建的空库**核对无误，再切换 `DATABASE_DSN`，不要直接覆盖正在用的库）：

```bash
# 数据库：先在 PostgreSQL 上建好空库 frameweave_restore（属主 frameweave），再导入
gunzip -c backup-20260101.sql.gz | docker run --rm -i -e PGPASSWORD='你的口令' postgres:18 \
  psql -h <主机> -U frameweave frameweave_restore
# 应用数据目录：解压回 APP_DATA_DIR 的上一级目录
tar xzf appdata-20260101.tar.gz -C /data/frameweave/prod
```

### 查看日志

```bash
# 默认打印最近 200 行后退出
bash deploy/deploy.sh logs --env prod backend
bash deploy/deploy.sh logs --env prod frontend

# 要实时跟着看就加 -f，按 Ctrl-C 退出
bash deploy/deploy.sh logs --env prod backend -f
```

## 七、常见问题

**Q：登录后台提示「用户名或密码错误」**
A：检查 `deploy/runtime/prod.env` 里的 `ADMIN_USERNAME` 和 `ADMIN_PASSWORD`。
任一为空时系统**不会**创建管理员账号（这是有意的安全设计）。填好后重启后端容器即可。
另外，同一账号连续输错 5 次会被锁定 15 分钟，锁定期内密码正确也进不去，等一会儿再试。

**Q：生成时提示找不到可用的模型渠道**
A：实际提示会是下面三条之一，对应三种原因：

- 「你还没有被分配到分组，无法使用 AI 能力，请联系管理员」——这个用户没归到任何分组。
- 「所属分组还没有配置模型渠道，请联系管理员在「分组管理」中添加」——该分组一条渠道都没配。
- 「所属分组没有可用的「某模型名」模型渠道，请联系管理员」——渠道有，但它的模型列表里
  没有这个模型名，或者这条渠道被停用了。

去「分组管理 → 该行「编辑」→ 模型渠道（本组专属）」核对模型名拼写和「启用 / 停用」开关。

**Q：生成成功但图片显示不出来**
A：多半是对象存储的桶没开**公共读**，或没配 **CORS**。桶需要允许你的域名跨域读取。

**Q：视频生成到一半就失败**
A：先看 Nginx 的 `proxy_read_timeout` 是不是太短（默认 60 秒不够，需要 600 秒）。

**Q：视频节点里找不到「视频编辑」「视频延长」两个模式**
A：这两档是 **Seedance 2.5 系专属**（模型名里带 `seedance-2-5`），2.0 系没有这两种任务类型，
界面上不会出现这两个按钮。换一个 2.5 的模型即可。走 OpenAI 兼容协议的其它视频模型只有「文生视频」一档。

**Q：用「视频编辑 / 视频延长」生成，提交成功、扣了钱，几十秒后才失败**
A：看报错是不是「提示词描述的意图与所选的生成模式不符」。上游收到请求只做一次前置校验，
真正跑任务时模型还会**结合提示词再判一次任务类型**，判出来与声明的不一致就异步失败（钱会退回）。
解法是在提示词里写明意图：编辑写「删除…」「增加…」「替换成…」「改成…」，
延长写「向后延长」「向前延长」「续写」。**这是上游的要求，不是本系统加的限制。**
如果本来就不想改动原视频，把模式改成「参考生视频」即可。详见第四章「视频生成模式」。

**Q：点「视频编辑」的生成按钮直接被拒，提示读不到时长 / 超出 4~30 秒**
A：这是**有意的拒绝，没有扣任何点数**。视频编辑的输出时长与源视频一致，所以计费按
**源视频的真实时长**算——服务端在扣费前会先读一次源视频的时长，读不到就没有任何诚实的收法，
宁可当场拒绝，也不按一个编出来的默认秒数收钱。检查那段视频是不是**公网可正常播放**的 mp4/mov，
以及时长是否在 **4~30 秒**之间（上游对待编辑视频的硬性要求）。

**Q：参考视频被拒，提示「疑似包含真人或隐私信息」**
A：上游会对参考视频做真人 / 隐私检测，**含真人的素材做编辑或延长会被拒**。
这是模型平台的内容策略，不是系统故障，重试、换分辨率、改提示词都没有用，请换一段不含真人的素材。

**Q：选了「图生视频」，点生成却报「需要连接图片节点（1 个），当前 2 个」**
A：这是**刻意的**。模式由用户显式声明，系统不会按素材数量替你猜，也不会在素材对不上时
偷偷换一个模式发出去——按钮上写着什么，发出去的就是什么。按提示调整参考素材，
或者改选「首尾帧 / 参考生视频」再生成。

**Q：上传大文件失败 / 画布同步失败**
A：先看提示文案。

- 看到「上传内容过大（上限 300MB），请压缩后重试」= 文件本身超过了系统上限。
  300MB 是写在代码里的硬上限，改配置突破不了（见第三章第 6 步的说明）。
- 没有中文提示、直接是 413 或网关错误 = 卡在 Nginx 那一层，
  检查 `client_max_body_size`（建议 600M）。

**Q：执行 `up` 直接报 `required variable DATABASE_DSN is missing a value: DATABASE_DSN is required`**
A：`deploy/runtime/prod.env` 里 `DATABASE_DSN` 没填。这是有意的 fail-fast——容器根本不会被
创建，宁可起不来，也不要连到一个空库上把数据写乱。`APP_DATA_DIR`、`FRONTEND_PORT`、
`NETWORK_NAME` 缺失时是同样的机制，报错里会点名是哪一项。

---

**Q：音频生成报「火山账号尚未开通「音频生成」服务」**

去火山引擎控制台 → **语音技术** → 开通「**音频生成**」。注意它和「语音合成」是两项独立资源，
开通语音合成不会自动带上它。另外**刚开通后有几分钟生效延迟**，期间还会报同样的错，等几分钟重试。

**Q：音频生成报「文本太长了……请分段生成」**

上游出片有 **120 秒**硬上限，文本读完超过这个长度就会被拒。中文约 3.8 字/秒（**450 字左右**
就到顶），英文约 9.5 字符/秒。虽然系统允许输入 2000 字，但中文远不到 2000 字就会撞时长墙，
请分段生成。文本框下方的字数计数器接近这条线时会变黄提示。

**Q：音频模型在画布的模型下拉里看不到**

两个原因：① 这个模型没加进**分组的渠道**「模型列表」里（模型是按分组给的，不是全局的）；
② 「系统 → 分级定价 → 模型类型与可用档位」里它的**类型不是「音频」**。检查这两处。

**Q：音频只有一个 5 点（或其它固定值）的扣费，没按字数算**

「系统 → 分级定价 → 音频模型按秒计费」表里，该模型的「**每 100 字积分**」还是 0。
填上就生效，不用重启。三种计价的优先级是：每 100 字 > 每秒 > 按次。

**Q：生成任务排队很久**

A：后端同时处理的生成任务数由 `GENERATION_JOB_CONCURRENCY` 控制（默认 16）。
并发上不去通常是这个值偏小，或者上游本身在限流。改 `deploy/runtime/prod.env` 里的
这一项后重启后端生效：

```bash
bash deploy/deploy.sh up --env prod backend
```
